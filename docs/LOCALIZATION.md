# Localization (#93)

STAR ARMADA ships English, German and Polish. A language is a **presentation**
choice: it changes what is drawn and nothing else, so two lockstep peers may play the
same match in two different languages and still agree on every ticksum.

## How a language is chosen

`Settings → Language` (page 4) cycles through the shipped packs and applies immediately;
the choice is stored in `saves/settings.json`:

```json
{ "language": "pl" }
```

A settings file naming a language this build does not ship is corrected on load
(`render/i18n.apply_from_settings`), so the row can never display a pack that is not there.

## Where the text lives

```
assets/data/lang/en.json    the catalogue — every string the UI can draw, msgid → English
assets/data/lang/de.json    German pack
assets/data/lang/pl.json    Polish pack
tools/lang_sources/*.py     the authored translations (generated into the JSON packs)
tools/lang_coverage.py      extracts the catalogue from the source and reports coverage
tools/build_lang_packs.py   writes the packs, refusing anything but exact key parity
```

A pack is a flat `msgid → translation` map plus a `names` section for data-driven names
(ships, stations, factions, tech, weapons, planets), keyed by the English display name:

```json
{
  "Settings": "Einstellungen",
  "MISSION COMPLETE": "MISSION ABGESCHLOSSEN",
  "names": { "Shipyard": "Werft", "Command Station": "Kommandostation" }
}
```

The msgid is the **exact English string as written in the source**, which is what makes the
lookup a one-liner at the drawing edge and keeps a pack reviewable against the UI.

## Where the lookup happens

At drawing edges only — a screen is translated without a single call site being touched:

| Edge | Covers |
|---|---|
| `clean_classic.Canvas.text` / `.button` | every classic menu screen (main menu, settings, campaign, briefing, LAN, save/replay browsers) |
| `clean_classic.main_menu` | the main menu, which draws its own labels outside the canvas |
| `menus._button` / `._title` | legacy menu screens drawn straight to the surface |
| `hud._label` | HUD panel headings, values and data names |
| `hud._wrapped_labels` | long help sentences, translated **before** they are word-wrapped |

Strings the UI assembles at runtime are not msgids, so they are asked for as templates:

```python
i18n.t('{outcome} — {name}', outcome=i18n.t('VICTORY'), name=player.name)
i18n.t('REFIT · LEVEL {level}/{max}', level=level, max=table['max_level'])
i18n.t('{credits} cr · {materials} mt · {energy} EN · {time}s', credits='1,050', ...)
```

`t()` returns any unknown string unchanged, and returns non-strings untouched, so a
drawing helper can call it unconditionally.

## Adding a string

1. Write the English literal at the call site as usual.
2. `python tools/lang_coverage.py --write` — refreshes the catalogue, prints what the
   packs are missing.
3. Add the translation to `tools/lang_sources/de.py` and `pl.py`.
4. `python tools/build_lang_packs.py` — writes the JSON packs and **refuses** to write if a
   pack is missing a key (a silent English fallback) or carries a key the catalogue no
   longer has (a dead translation).
5. `python tools/diag_i18n.py` — checks geometry, truncation and lookup coverage.

Strings the scanner cannot harvest must be listed in `EXTRA_UI_KEYS`
(`tools/lang_coverage.py`): templates assembled with `str.format`, and unit words such as
`hull` that read as an id because they are lowercase.

## What is deliberately not translated

* **Diagnostics and logs** — internal messages, not player-facing.
* **Number formatting** — thousands separators stay locale-independent (`1,050`), so a
  bill reads the same in every pack. Tracked as a separate concern from text.
* **Runtime flash messages** assembled by the input layer (`attack <name>`) — they are
  built from live values in several places; tracked as a follow-up.

## Two rules the drawing edges follow

* **Suffixes are not msgids.** Rows that read as click-to-cycle arrive at the canvas
  already suffixed (`Blue ›`, `Team 2 ›`, `NORMAL ›`). The canvas looks up the name alone
  and puts the affordance back; translating the whole string would miss every time, and
  stripping the suffix without restoring it removes the only cue that the row cycles.
  Long help text follows the same order in the other direction: translate *first*, then
  word-wrap, because a wrapped fragment is not a msgid either.

* **A saved language is process-wide, so fixtures pin the settings file.** `MenuStack`
  applies the saved language before the first frame, which means a test that builds one
  now renders in whatever language is in that file. `render/menus.py` freezes
  `USER_DIR`/`SAVES_DIR`/`SETTINGS_PATH`/`CAMPAIGN_PATH` at *import*, so patching
  `USER_DIR` inside a test does not move `SETTINGS_PATH`; every menu fixture patches
  `SETTINGS_PATH` (to a temporary file) **before** any `MenuStack` exists. Without that, a
  developer's own Polish save leaked into unrelated tests — mission-card geometry, the
  replay library, the skirmish roster — and the failures looked like layout regressions.

## Tests

`tests/test_i18n.py` pins the pack contract (every catalogue key translated, no dead keys,
high-signal labels are not identity mappings), the lookup behaviour (fallbacks, templates
with missing fields, unknown codes), the Settings integration (saved language applied
before the first frame, the row cycles and persists, every row stays reachable), the HUD's
single drawing edge (a panel label is looked up there *and* the translation reaches the
canvas — a lookup that happens and is then dropped cannot pass) and the invariant that
matters most: **no module under `game/` may reference `render.i18n`**, and two peers in
different languages agree on `lan.precise_checksum`.

The doubles that spy on `HUD._label` mirror its real signature, `translate` included: a
spy that cannot be called the way production calls it raises instead of asserting.

`tools/diag_i18n.py` renders the menus and the station panel in all three packs and checks
that button geometry is identical across languages, that no translation is truncated with
the ellipsis the canvas draws when a string does not fit where English fits, and that every
string the HUD asks to translate is a catalogue key.
