Design/registration integration facts:
  - build_args / export_args are optional JSON lists of strings; explicit null
    and non-string members are rejected. Absent fields preserve legacy defaults.
  - B6 selectors retain ship:imperial:corvette exactly; B4 selectors retain
    rebel:defense_satellite. No --replace-seed is appended.
  - B4/B6 recipes only save a .blend, not a runtime mesh. Script build therefore
    runs the seed with build_args and then its guarded export_script with
    export_args in the same isolated tools/art dependency workspace.
  - A declared export-only wrapper exports the existing master directly for
    export-model, regardless of source authority. Legacy trio rows without a
    wrapper retain the combined generator/export path, now isolated for build
    as well as export.
  - Approved runtime hashes are checked before publishing reconstructed outputs.
    Derived binary .blend bytes need not reproduce byte-for-byte. Existing pinned
    sources are preserved by default, local drift is rejected before rebuilding,
    and returned source provenance identifies the actual retained source.
  - Existing explicit --keep-blend behavior remains for script builds only,
    after runtime verification. Missing script-derived sources may be recreated.
    Export never publishes a source, even with --keep-blend.
  - Existing-master refusal guards are unchanged and exercised using exact
    production B4/B6 preflight prefixes without importing Blender.
